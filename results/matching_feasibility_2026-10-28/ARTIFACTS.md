# Matching feasibility artifacts

The public pool comes from the pinned official Persona Vectors `dataset.zip`, using Hallucination Normal and Hallucination II answers to 1,024 paired questions. Source identities, archive checksum and training-pool selection remain in `../controlled_sft_2026-10-28/`. This pool was used in that earlier SFT pilot; the current work is exploratory selection analysis, not a new held-out behavioural experiment.

- `manifest.json` freezes the new configuration, scoring rubric, script/helper hashes, prior-run inputs, model revision and existing persona vector. `executed_source/` contains the exact new code/configuration/launcher. The remote checkout retained its earlier parent commit with working files; hashes identify the actual execution, independent of the local Git publication state.
- `inputs.jsonl` contains the public QA pairs and saved activation projections/token counts. `judge_prompt.txt` contains the official rubric. Only question/answer text was sent to the judge; source labels and activation scores were omitted.
- `raw_responses.jsonl`, `judgements.jsonl`, `judge_usage.jsonl` retain every API response, weighted numeric score, numeric probability mass, and returned model/provider/usage. The alias and logprob procedure match the preceding pilot; snapshot equivalence is not established. No API credentials are included.
- `scored_pool.jsonl` joins the full public QA pool to its text scores and projections. `summary.json`, `score_overlap.png`/`.pdf` report the completed scoring measurements. This stage uses raw base-model projection, not projection difference.
- `matching_results.json`, `feasibility_table.md`, `candidate_matches/` retain the predeclared matching analysis and sensitivity cases with a 20% token-length-ratio limit. Counts are greedy feasible matchings; the algorithm prioritizes the largest target-score gap and does not optimize global covariate balance.
- `balance_audit.py`, `length_exact/analysis_protocol.json`, and `length_exact/` record the separately labelled post-hoc response to observed length imbalance. They reuse identical API scores and require exactly equal token counts. Candidate IDs are for feasibility inspection, not approved training subsets. The raw backup also retains the duplicate score files needed to rerun this directory independently.
- `additional_text_audit.json` reports means of the existing fixed caveat score for the exact-length primary matches, joined by ID from the preceding run's `training_score_comparison.jsonl`. `illustrative_pairs.json` preserves the first two pairs in the algorithm's ordering; examples were not selected using SFT outcomes.
- `verification.json` records successful per-pair checks of uniqueness, question reuse, score calipers/gaps, source restrictions and length constraints across 19 nonempty matching cases. Main pipeline exit was 0, with no failed API requests or missing scores.
- `backup_manifest.json` covers 56 raw files / 14,981,816 bytes, all verified locally against remote SHA-256 and byte sizes. The complete backup is `runs/matching-feasibility-2026-10-28/` (Git-ignored); it includes all logs, duplicate sensitivity inputs, execution timestamps and source snapshots. `shutdown_and_backup.json` was written locally after verified shutdown and is outside that earlier manifest.

All judging, matching, statistics and figure generation ran on the approved remote Pod, with `CUDA_VISIBLE_DEVICES` empty and no target-model loads. Local actions were file inspection, editing, transfer, checksum verification and image viewing. The reused Pod is stopped; its persistent workspace continues storage billing. No new SFT was run.
